# 旅行推銷員問題（TSP）：五種方法比較
# 五種方法
貪婪演算法的做法是每一步都走到最近的未訪問城市。它速度極快（O(n²)），實作也最簡單，缺點是太短視，早期的選擇常讓後面被迫走很長的回頭路。

改良法（2-opt）是在既有路徑上反轉其中一段，只要總長變短就接受，一直做到無法再改善為止。它能大幅改善現有的解，但只會停在局部最佳，品質取決於起點。

爬山演算法是隨機交換兩個城市的位置，只接受變好的結果。它是最簡單的方法，但因為不接受變差的解，很容易卡在局部最佳。

模擬退火法和爬山類似，但變差的解也會以機率 exp(−Δ/T) 被接受，溫度 T 再逐步降低。高溫時可以跳出局部最佳，低溫時逐漸收斂，所以品質好，不過要調整溫度與降溫速度，且帶有隨機性。

梯度下降法無法直接用在離散的路徑上，必須先連續化。我用的是彈性網路：一個環被城市拉向各自的位置，同時靠張力保持平滑，沿能量函數的梯度更新，最後依環上位置排出順序。它概念獨特，但對參數敏感（步長太大會發散），實用性不如前幾種。

# 實驗結果

我用同一組隨機城市實際執行，並用動態規劃算出最佳解作對照。

第一組是 12 個城市，最佳解為 355.97。貪婪與改良法都比最佳解長 2.3%，爬山長 14.0%，模擬退火與梯度下降都找到最佳解。

第二組是 15 個城市，最佳解為 364.75。貪婪長 21.3%，爬山長 9.4%，改良法、模擬退火與梯度下降都找到最佳解。

# 重點觀察

貪婪最快，但品質不穩定，兩組資料的差距從 2.3% 到 21.3%。

改良法適合接在貪婪後面。15 城市那組它把貪婪解改良到最佳；12 城市那組則沒有進步，因為貪婪解本身已經是 2-opt 的局部最佳。

爬山因為不接受變差的解，兩組都表現最差。

模擬退火在兩組都找到最佳解，是這幾種裡最穩的。

這些結果都只是單次執行，樣本也只有兩組，不能就此斷定哪個方法普遍較好。
